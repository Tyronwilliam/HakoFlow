# Commands

- `bun dev` — dev server · `bun run build` — prod build
- `bun test` (Vitest, run) · `bun test:watch` · `bun test:e2e` (Playwright)
- `bun lint` · `bun typecheck` · `bun format`
- `bun gen:api` — regenerates Supabase types (`src/types/database.types.ts`) + table-types + openapi. Sub-commands: `gen:types`, `gen:table-types`, `gen:openapi`
- `bun seed-supabase` / `bun seed-mock-data` — seed DB / mock data

# Map of `src/`

HakoFlow = unified multi-channel inbox (Gmail, Discord, Slack): messages arrive via webhooks, are linked to contacts/conversations, with merge suggestions and AI (summary/reply suggestion).

## Features (`src/features/<feature>/`)

Each feature follows the pattern `api.ts` (URL constants) / `adapters` (raw DB → front shape + zod response schemas) / `validators` (zod on the input side) / `hooks` (Tanstack Query) / `actions` (Server Actions) / `components`. Full details: `docs/architecture-patterns.md` — **read before creating or modifying a feature**.

- `inbox/` — conversation list, grouping by contact (`use-conversations`, `conversation-list`, `contact-group-*`)
- `message/` — message feed of a conversation (`MessageFeed`, `use-messages`)
- `contact-linking/` — linking channels to a contact + merge suggestions + merge and link history, both undoable (`link-contact-dialog`, `merge-suggestion-*`, `merge-history-*`, `link-history-*`, `contact-management-tabs`, hooks `use-link-*`, `use-merge-suggestion*`, `use-contact-merges`, `use-undo-merge`, `use-contact-link-history`, `use-undo-link`, Server Actions `undo-merge`, `undo-link`)
- `contacts/` — contact list
- `reminders/` — reminders (writes via Server Actions, no API route)
- `channels/` — per-channel integrations: one folder per channel (`gmail/`, `discord/`, `slack/`) with `client.ts` (external API calls), `parser.ts` (webhook payload → message), `identity.ts` (contact's native identifier), `types.ts`. Common: `shared/` (`ContactIdentity`, `normalize-email`)
- `ai/` — Anthropic calls (`suggest.ts`, `summarize.ts`), client in `src/lib/anthropic.ts`
- `auth/` — Supabase login (Server Action `sign-in`, Google button)

## Routes (`src/app/`)

- `(app)/` — authenticated pages: `inbox` (+ `inbox/[id]` = conversation detail), `contacts` (+ `contacts/gestion` = Contact management page: channel linking, merge suggestions, history), `reminders`, `settings`, `stats`
- `(auth)/` — `login` + OAuth `callback`
- `api/` — GET route handlers (conversations, messages, contacts, contact-linking, contact-merges, merge-suggestions, reminders, ai): they run the Supabase `select` then delegate to the feature's adapters. `api/webhooks/{discord,slack,stripe}` — incoming ingestion
- `src/proxy.ts` — Next.js 16 proxy (ex-middleware), refreshes the Supabase session via `src/lib/supabase/proxy.ts`

## Shared

- `src/lib/api.ts` — `fetchApi` + `parseApiResponse` (use in hooks, no manual fetch/parse)
- `src/lib/supabase/` — `client.ts` (browser), `server.ts` (RSC/route handlers), `proxy.ts` (session)
- `src/types/shared/` — `XxxRow` types mirroring the DB tables (generated by `gen:table-types`); `database.types.ts` is generated, never edit by hand
- `src/components/` — `ui/` (Shadcn, generated), `shared/` (including `QueryBoundary` for loading/empty/error), `base/`, `layout/`
- `src/mocks/` — Faker factories + MSW handlers (tests and seed)

# Conventions

- After adding/removing a feature, a route or an npm script: update the "Map of `src/`" and "Commands" sections above
- API responses always validated with zod (`.parse`, not `.safeParse`) in hooks; an invalid payload must throw
- Never hardcode `/api/...` URLs: use a constant in the feature's `api.ts`
- Database writes via Server Actions + `useActionState` (`validators/` validation with `safeParse`)
- Loading/empty/error of a list: always `<QueryBoundary>`, never the three `if`s by hand
- Colors: theme variables only (`docs/theme.md`), nothing hardcoded
- Commits: Conventional Commits (commitlint), e.g. `fix(contact-linking): ...`
- Tests: factories/handlers in `src/mocks/` (see `docs/vitest.md`)

What the app does

A unified multi-channel inbox that:

1. Ingests messages via webhooks (Gmail, Discord, Slack → api/webhooks/)
2. Links each message to a contact/conversation, with a native identifier per channel
   (channels/\*/identity.ts)
3. Detects duplicates — if the same person exists under several channels, the app suggests
   merging the identities (contact-linking/, merge-suggestion-\*)
4. Groups conversations by contact rather than by channel (inbox/contact-group-\*) —
   a "person" view rather than a "mailbox" view
5. Assists with AI (Claude via src/lib/anthropic.ts): thread summary,
   reply suggestion (features/ai/)
6. Enables follow-up via reminders (reminders/) so no conversation is left without
   a reply
7. Provides a consolidated stats and contacts view

In short

It's a lightweight CRM / unified helpdesk for freelancers and small teams, positioned between
a simple mail client and a real heavy CRM (like Hubspot/Intercom) — with AI as the glue to
reduce human handling time. The key value proposition is cross-channel identity
merging: no longer seeing "a Discord ticket" and "an email" as two different
people, but as a single contact with a continuous history.
